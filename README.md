# RemnaNode Node Forge

Однофайловый установщик веб-мастера RemnaNode для Ubuntu и Debian. Он ставит
Docker Engine, Docker Compose, Nginx и Certbot, создаёт `/opt/remnanode` и
показывает адрес панели после установки.

## Быстрая установка

Для публичного репозитория:

```bash
curl -fsSL https://raw.githubusercontent.com/usupix/remnanode-node-forge/main/install-remnanode-manager.sh | sudo bash
```

В конце появятся уникальный адрес и пароль, например:

```text
Open: http://203.0.113.10/4f82c0d8a191e724/
Password: generated-password
```

Путь состоит из 16 случайных символов. Backend панели остаётся на
`127.0.0.1:8765`, а наружу его публикует Nginx только по этому пути. Данные для
входа также сохраняются в `/root/remnanode-manager-access.txt`.

> Первоначальный адрес на IP использует HTTP. Для подключения логов через
> одноразовый код домен и сертификат ноде не требуются: рабочий ключ нода
> получает самостоятельно по исходящему HTTPS. Пароль самой панели при HTTP
> остаётся незашифрованным; используйте HTTPS для постоянного администрирования.

## Что умеет панель

- принять полный `docker-compose.yml` из Remnawave, проверить и отдельно сохранить его;
- получить актуальные теги `remnawave/node` из Docker Hub и выбрать нужную версию либо `latest`;
- фоном скачать выбранный образ, запустить ноду и показать живой прогресс установки;
- автоматически добавить read-only volume сертификатов Xray;
- показать все публичные IPv4/IPv6 сервера, проверить выбранный адрес против A/AAAA и выпустить сертификат Let's Encrypt;
- положить `.pem` и `.key` в `/var/lib/remnawave/configs/xray/ssl`;
- обновлять сертификаты deploy-hook’ом Certbot и перезапускать ноду;
- создать для каждого сертификата уникальный статический Nginx-сайт с favicon,
  `robots.txt`, JSON-статусом, корректными `404`, обычным HTTPS на TCP `443`
  (если порт не занят другим процессом) и TLS fallback на `127.0.0.1:8443`;
- генерировать VLESS Reality self-steal и Hysteria 2 inbound;
- независимо включать BBR, TCP Fast Open, MTU probing, VPN-буферы и очереди;
- возвращать снятые сетевые настройки к значениям, сохранённым при установке;
- добавить публичный OpenSSH-ключ для root, выбрать новый SSH-порт и включить или выключить парольный вход;
- безопасно менять SSH в два этапа: сначала держать старый и новый порты параллельно, затем убирать старый после проверки;
- откатывать SSH-конфигурацию из автоматической резервной копии;
- показывать состояние контейнера, образ и перезапуски без перезагрузки страницы;
- транслировать в браузер `docker logs -f` и `docker exec remnanode xlogs`;
- передавать Xray access log в MelTun для истории подключений по пользователям;
- создавать резервные копии Compose, Nginx и sysctl перед изменениями.

Официальная последовательность Remnawave сохранена: Docker → каталог
`/opt/remnanode` → Compose из карточки ноды → `docker compose up -d`.

## История подключений в MelTun

1. В веб-админке MelTun откройте **Ноды → Сбор логов Xray**, укажите уникальный
   ID и публичный IP ноды, затем получите одноразовый код на 10 минут.
2. Запустите обновлённый установщик Node Forge на ноде. Сохраните Compose в
   Node Forge: к `remnanode` добавится монтирование `/var/log/remnanode`.
   Затем пересоздайте контейнер ноды кнопкой установки/обновления.
3. В конфигурационном профиле Xray в панели Remnawave включите запись access
   log. В профиле должен быть объект:

   ```json
   "log": {
     "access": "/var/log/remnanode/access.log",
     "error": "/var/log/remnanode/error.log",
     "loglevel": "warning"
   }
   ```

4. Перезапустите установщик Node Forge на каждой ноде. Откройте панель по
   прежнему адресу `http://IP/СЕКРЕТНЫЙ_ПУТЬ/` и в форме **Передавать
   подключения в Meltun** введите тот же ID и одноразовый код. Нода обменяет
   его на собственный рабочий ключ через `https://meltun.org`; код больше не
   действует. Публичный IP, указанный при выдаче кода, должен совпасть с IP,
   с которого нода выходит в интернет. Укажите часовой пояс логов Xray
   (обычно UTC).
5. В веб-админке MelTun проверьте поле «Последний пакет» у каждой ноды. В карточке
   пользователя появятся время, исходный IP, адрес назначения и нода.

Если код истёк или IP не совпал, выдайте новый код в MelTun. Рабочий ключ не
показывается в браузере и хранится на ноде в файле с правами `0600`.

Сборщик отправляет пакеты по HTTPS, подтверждает смещение файла после ответа
сервера и переживает перезапуск. Сами access log файлы вращаются ежедневно и
хранятся до 30 дней. Для определения страны по IP поместите
`GeoLite2-Country.mmdb` в каталог `geoip` веб-проекта MelTun. Трафик по нодам
берётся из Remnawave; Xray access log не содержит байты по каждому сайту.
Некоторые виды трафика могут не попадать в access log Xray. История фиксирует
только соединения, прошедшие через ноду, и не раскрывает HTTPS-пути или
содержимое запросов.

## Безопасная смена SSH

В карточке **SSH: ключ, порт и пароль** вставьте только публичный ключ вида
`ssh-ed25519 AAAA...`, выберите порт и нажмите **Подготовить SSH безопасно**.
Панель проверит ключ через `ssh-keygen`, сохранит резервную копию и поднимет
новый порт параллельно текущему. Откройте вторую SSH-сессию на новом порту и
только после успешного входа введите номер порта в поле подтверждения.

Добавленный ключ хранится в защищённом файле
`/var/lib/remnanode-manager/root-authorized_keys`. OpenSSH проверяет и его, и
обычный `/root/.ssh/authorized_keys`, поэтому существующие ключи не заменяются,
а веб-службе не требуется доступ на запись в домашний каталог root.

Если снять флажок парольного входа, Node Forge выставит
`PasswordAuthentication no`, `KbdInteractiveAuthentication no` и
`PermitRootLogin prohibit-password`. Это разрешено только когда у root уже есть
хотя бы один корректный публичный ключ. Кнопка отката возвращает конфигурацию,
которая была до подготовительного этапа.
